# Scaffolded snapshot (lab 2 - reverse engineering)

This folder is the lab 2 "reverse engineering" deliverable: `ScaffoldedAstraKaContext.cs` and
`Models/*.cs` were generated by pointing `dotnet ef dbcontext scaffold` at the live `AstraKa`
database and letting it read the schema back into C# - the opposite direction from the
hand-written Code First model in `AstraKa.Domain`/`AstraKa.Infrastructure`.

**This folder is intentionally inert.** There is no `.csproj` here, it is not listed in
`AstraKa.slnx`, and nothing in the solution references it, so `dotnet build api/AstraKa.slnx` never
touches it. It is a point-in-time snapshot kept for the lab report/defense, not running code.
`AppDbContext` and the entities under `AstraKa.Domain/Entities` remain the one source of truth for
the actual application.

## How it was generated

```
dotnet ef dbcontext scaffold ^
  "Server=(localdb)\MSSQLLocalDB;Database=AstraKa;Trusted_Connection=True;TrustServerCertificate=True" ^
  Microsoft.EntityFrameworkCore.SqlServer ^
  --project api/src/AstraKa.Infrastructure --startup-project api/src/AstraKa.Api ^
  --output-dir ../../scaffold/Models --context-dir ../../scaffold ^
  --context ScaffoldedAstraKaContext --no-onconfiguring --force
```

- `--project`/`--startup-project` just supply the EF Core tooling and the SqlServer provider
  (already referenced by `AstraKa.Infrastructure`) to run the command - the output itself is
  redirected two directories up and out of that project entirely via `--output-dir`/`--context-dir`,
  which is why nothing here is ever picked up by `AstraKa.Infrastructure`'s own build.
- `--no-onconfiguring` is deliberate: without it, EF would embed the connection string (including
  the server name) directly in `ScaffoldedAstraKaContext.cs` as committed code. With it, the
  generated context has no `OnConfiguring` override and no connection string at all.
- `--force` lets the command overwrite these files if it's ever re-run against a changed schema.
- The namespace in the generated files (`AstraKa.Infrastructure`) comes from the `--project` used to
  run the tool; it's cosmetic here since these files are never compiled into that project.

Scaffolding only reads schema metadata (tables, columns, keys, indexes) - it does not care what rows
happen to be in the database, so it can be re-run at any time against the current `AstraKa` database.
